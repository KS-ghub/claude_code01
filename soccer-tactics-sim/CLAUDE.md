# CLAUDE.md — サッカー戦術シミュレーション 開発ガイド

このリポジトリはPython標準ライブラリのみで動くサッカー戦術シミュレーション。
プロジェクトの全体像・仕様・開発経緯は `README.md` を必ず先に読むこと。
このファイルはClaude Codeでの開発作業に必要な実務情報(実行・検証・規約・バックログ)をまとめる。

## プロジェクトの目的

サッカー戦術の分析ツールとして使う:
- 戦術ごとの得意・不得意な相手(相性)の洗い出し
- 勝率を上げるためのパラメータ調整の実験
- 典型的なパスコース・得点パターンの抽出
- **デゼルビ(Roberto De Zerbi)のポゼッション戦術の再現**が中期目標。
  ビルドアップ(GK込み3枚で相手を引きつけて空いた方へ逃がす)、ハーフスペース支配、
  偽9番/偽SB、「2つ進んで1つ戻る」リズムなどの要素は実装済み(README「3. 仕様概要」参照)

## 実行・検証コマンド

追加パッケージ不要。Windowsでは `python`、macOS/Linuxでは `python3`。

```bash
python run_preview.py        # 36秒分のクイック動作確認(コード変更後は必ず実行)
python run_match.py          # 1試合フル実行 → match_result.txt / match_full_half.csv
python run_10_matches.py     # 10試合集計 → match_10games_result.txt
python run_10_matches_separate.py  # 10試合を個別ファイルに出力
```

**変更後の検証チェックリスト**(すべてmatch_result.txt末尾/集計で確認できる):
1. `python -c "import players, formation, ball_logic, tactics, engine"` が通ること
2. `run_match.py`実行後、`座標範囲外の選手数=0`・`csv総行数の一致=True`であること
3. ゴールが1試合あたり数点発生していること(0-0連発や2桁得点の頻発はバランス破壊のサイン)
4. 複数シードで確認すること(1シードの結果はノイズが大きい。バランス確認は20〜30試合単位で)

## アーキテクチャ

依存方向: `run_*.py` → `engine.py` → `players.py` / `formation.py` / `ball_logic.py` / `tactics.py`

- `engine.py` — `MatchSim`クラス。1秒1ステップ、45分=2700ステップ。ボールアクションの
  意思決定は平均3秒に1回(`ACTION_PROB_PER_STEP`)。攻撃側の保持者以外はオフサイドラインの
  手前でターゲット位置をクランプする処理もここにある。
- `ball_logic.py` — 意思決定と確率判定のすべて(`resolve_ball_action`が入口)。
  パス/クロス/カットバック/スルーパス/シュート/ミドル/バックパス/GK配球/オフサイド。
  距離系定数は「旧グリッド1マス≒5m」からの換算(`SCALE=5`)。
- `formation.py` — フォーメーション(442/433/352)ごとの基準ポジションと追随ロジック。
  偽9番・SB役割(fb_role)の位置補正は`get_default()`にある。
- `players.py` — フォーメーションごとの選手構成・能力配分(チーム合計1000点)。
- `tactics.py` — 戦術プリセット5種。formation + 4軸(line_height/width/pass_risk/
  press_intensity) + false_nine + fb_role。

## 変更時の規約(壊しやすいポイント)

- **ポジションキーの先頭は必ず `GK` / `DF_` / `MF_` / `FW_`**。ball_logic側のstartswith判定の前提。
- **サイドのポジションは末尾サフィックスを`ball_logic.WIDE_POS_SUFFIXES`に含める**
  (LB/RB/LM/RM/LW/RW/LWB/RWBは登録済み)。列挙し忘れるとサイド判定から漏れる。
- **能力合計は必ず1000点**(`players.py`にassertあり)。
- **背番号10=キックオフ時のボール保持者(中央FW)**。engine側の前提。
- **フォーメーション追加手順**: `players.FORMATIONS`と`formation.FORMATION_TABLES`に
  同じキーでエントリを追加し、`tactics.py`のプリセットに`"formation"`キーを設定するだけ。
  4-3-3/3-5-2の追加時のパターンを踏襲すること。
- **座標はA基準で定義しBはミラー生成**。formation.pyの補正(偽9番等)はミラー前のA基準座標に
  対して行うこと(`get_default`内のコメント参照)。
- **CSVスキーマ(列構成)を変えるとビューア(match_playback.html)が壊れる**。列追加時は
  ビューアのparseCSVも更新する。イベント種別を追加したときはビューアのdescribeEventの
  ラベル表にも追加する。

## 過去にハマった不具合(再発防止)

- 1秒刻み化でアクション判定頻度が3倍になりターンオーバー激増 → 意思決定は平均3秒に1回に分離
- 距離系定数のメートル換算漏れ(前進ボーナス2マス=2m問題) → 定数追加時はSCALE換算を意識
- 3-5-2のFW間隔が広すぎてシュートの84%が枠外 → FWの基準colはゴールエリア(列30〜36)を意識
- ウイングバックのline_height感度が高すぎて攻撃時も引き戻された → 感度は役割に応じて設定
- オフサイド導入直後に約200回/試合発生 → 攻撃側のライン手前クランプ+3m許容幅で約15回に正常化
- CSVイベントの記録先が「アクション後の保持者」になっていて失点側にGOALが付くバグ
  → engine.run_stepでアクション前の保持者を`acting_team/acting_num`として保存してから記録

## 環境の注意(Windows)

- コンソール出力の日本語はcp932の関係で文字化けすることがある。**判定はコンソールではなく
  出力ファイル(match_result.txt等、UTF-8)を読んで行う**こと。
- `match_full_half.csv`を開いたままrun_match.pyを実行するとPermissionError(ファイルロック)。
  少し待ってリトライすれば解消する。
