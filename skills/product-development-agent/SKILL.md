# 製品開発エージェント（IPパッケージ組み合わせ提案）

## 目的

顧客ニーズ（自然文）を入力として受け取り、社内に蓄積された IPパッケージ Skills（`ip-package-*` という命名規則のSkill群）の中から関連度の高いものを自動検索し、単独利用または複数組み合わせによる新製品・サービスの企画案を提示する。

このSkillは検索対象データ（IPパッケージ本体）を持たない。判断材料はすべて以下のSkill群のfrontmatterと本文から取得する。
- `ip-package-*`：技術資産の実体（特許・ノウハウ・ソフトウェア）
- `ip-scenario-*`：知財部が提供する支援サービスセット（IPオファリングの組み合わせ方の型）
- `ip-offering-*`：知財部の個別サービスメニュー（ノウハウ保護、発明発掘、特許出願、知財契約、価値評価）

## 処理手順

### STEP 1: 顧客ニーズのヒアリング・構造化

ユーザーから顧客ニーズを受け取ったら、以下を整理する（不明な点があれば質問する）。
- 誰の課題か（業界・部門・企業規模）
- 解決したい課題（現状の困りごと）
- 期待する効果（定量目標があれば）
- 制約条件（予算感、導入時期、社外提供の可否など）

### STEP 2: IPパッケージ候補の横断検索

利用可能な `ip-package-*` Skillをすべて確認し、以下の観点でスコアリングする。
1. `description` およびキーワード節との一致度（課題領域・技術ドメインが合致するか）
2. `使用実績・使用用途` に類似ユースケースの記載があるか
3. `関連契約` の用途制限に抵触しないか（社外提供が前提の場合、既存契約の相手先限定条項に注意）

該当候補が複数ある場合は、単体で十分か、組み合わせが必要かを判断する。組み合わせ例：
- 画像認識検品（IP-PKG-001）× IoT予知保全（IP-PKG-002）→「製造ライン統合品質・保全プラットフォーム」
- IoT予知保全（IP-PKG-002）× 需要予測（IP-PKG-003）→「稼働状況と需要変動を連動させた生産計画最適化」

### STEP 3: 契約・権利関係の確認

候補となった各IPパッケージの「関連契約」節を確認し、以下を明示する。
- 既存の開示先限定・用途制限に抵触しないか
- 社外提供する場合、新規ライセンス契約や既存契約の相手先条項変更が必要かどうか
- ノウハウ文書（NDA対象）を顧客に見せてよい範囲はどこまでか（通常は「概要レベルのみ開示可、詳細仕様は契約締結後」）

抵触の疑いがある場合は企画案に明記し、法務・知財部門への確認を促す。**契約解釈の最終判断はしない。**

### STEP 3.5: IPシナリオの選定

STEP2・STEP3の結果に応じて、`ip-scenario-*` Skillから最も適したものを選ぶ。判断基準：

| 状況 | 選ぶシナリオ |
|---|---|
| STEP2で該当IPパッケージが**見つからない**（新技術開発が必要） | [[ip-scenario-new-product-from-invention]]（新規発明起点型） |
| STEP2で**既存の複数IPパッケージ**を組み合わせて社内事業として提供する | [[ip-scenario-ip-package-cross-offering]]（既存IPパッケージ組み合わせ提供型） |
| 提供先が**社外（取引先・パートナー）へのOEM／ライセンス外販** | [[ip-scenario-oem-license-provision]]（外部OEM・ライセンス提供型） |

該当するシナリオが定型パターンに合わない場合は、`ip-offering-*`（ノウハウ保護／発明発掘／特許出願・権利化／知財契約／知財価値評価）を個別に組み合わせて即席のシナリオ案を提示してよい。その場合も既存シナリオSkillと同じ「順序・タイミング・成果物」の形式で示す。

### STEP 4: 企画たたき台の生成

以下の構成で出力する。

```
## 顧客ニーズ
（STEP1の整理内容）

## 提案する組み合わせIPパッケージ
- IP-PKG-XXX（パッケージ名）: 採用理由
- IP-PKG-YYY（パッケージ名）: 採用理由（複数の場合）

## 新製品・サービス案
- コンセプト
- 主要機能（各IPパッケージのどの資産に由来するか明記）
- 想定される差別化ポイント

## 権利・契約面の留意事項
- 各IPパッケージの用途制限との整合性
- 追加で必要な契約（ライセンス変更、新規NDA等）

## 知財部の支援計画（IPシナリオ）
- 適用するIPシナリオ：（該当シナリオ名、または即席組み合わせ案）
- 構成するIPオファリングと関与タイミング：
  - （オファリング名）：（タイミング）
  - （オファリング名）：（タイミング）
- 事業部側でこのタイミングで準備すべきこと

## 未確認事項・次のアクション
- 法務・知財部門への確認事項
- 追加開発が必要な機能
```

## 注意事項

- このSkillは企画の「たたき台」を作るものであり、最終的な事業判断・契約締結の可否判断は行わない。
- 新しいIPパッケージ・IPシナリオ・IPオファリングSkillが追加された場合、命名規則（`ip-package-*` / `ip-scenario-*` / `ip-offering-*`）を維持していれば自動的に検索対象に含まれる。
- 存在しないIPパッケージ・シナリオ・オファリングや実績を創作しないこと。該当候補がなければ「該当するIPパッケージなし」等と正直に報告する。
