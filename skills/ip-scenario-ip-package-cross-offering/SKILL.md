# IPシナリオ：既存IPパッケージ組み合わせ提供型

## 概要

新規の発明発掘・特許出願を伴わず、既に社内に蓄積された複数のIPパッケージ（例：画像認識検品＋IoT予知保全）を組み合わせて、事業部が新製品・サービスとして顧客に提供するケースに適用するシナリオ。論点の中心は「新規権利化」ではなく「既存の契約上の用途制限との整合性確認」と「提供条件（ライセンス料率等）の設計」になる。

## 想定シーン

- [[product-development-agent]] のSTEP2で複数の既存IPパッケージが候補として見つかったとき（例：製造ライン統合品質・保全プラットフォーム提案）
- 事業部から「このIPパッケージ、他の案件にも使えないか」という相談があったとき

## 組み合わせるIPオファリング（順序）

| 順序 | オファリング | タイミング（目安） |
|---|---|---|
| 1 | [[ip-offering-ip-contract]] 知財契約（既存契約の抵触チェック） | 企画確定直後、最優先で実施 |
| 2 | [[ip-offering-ip-valuation]] 知財価値評価（ライセンス料率設計） | 抵触チェック完了後、社外提供する場合 |
| 3 | [[ip-offering-ip-contract]] 知財契約（新規契約締結） | 顧客・パートナーとの条件合意後 |
| （必要時） | [[ip-offering-knowhow-protection]] ノウハウの特定・保護 | 開示範囲の見直しが必要な場合 |

## 事業部との関与タイミング

- **企画確定直後**：知財部へ一報し、対象IPパッケージの既存契約（開示先・用途制限）を確認（[[product-development-agent]] STEP3に対応）
- **契約整合性OK後**：価値評価・ライセンス料率設計、顧客との条件交渉
- **提供開始前**：新規契約締結、IPパッケージ台帳の関連契約節を更新

## 成果物

- 既存契約との抵触チェック結果
- 新規ライセンス契約／利用許諾契約
- 更新後のIPパッケージSKILL.md（関連契約節の追記）

## 留意事項

- 複数IPパッケージを組み合わせる場合、パッケージごとに契約相手先・用途制限が異なることが多く、**個別に整合性チェックが必要**（一括判断は不可）
- ノウハウ文書（NDA対象）は組み合わせ提案の段階では概要開示に留め、契約締結後に詳細開示する運用を徹底する
